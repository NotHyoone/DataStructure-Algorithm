## 1. 이 코드가 전체적으로 하는 일

파일: [`HW3.java`](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java)

이 코드는 **좌표 압축**을 수행합니다.

예를 들어 입력이:

```text
5
2 4 -10 4 -9
```

이면, 정렬된 서로 다른 값은:

```text
-10, -9, 2, 4
```

각 값보다 작은 **서로 다른 값의 개수**는:

- `-10 -> 0`
- `-9 -> 1`
- `2 -> 2`
- `4 -> 3`

그래서 원래 순서대로 결과는:

```text
2 3 0 3 1
```

이 됩니다.

## 3-1. `main(String[] args)`

위치: [`HW3.java` 17행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L17)

```java
public static void main(String[] args) {
```

### 역할
자바 프로그램의 **시작점(entry point)** 입니다.  
프로그램을 실행하면 JVM이 가장 먼저 이 메서드를 호출합니다.

- `void`: 반환값 없음

이 코드에서는 `args`는 사용하지 않습니다.

## 3-5. `arraycopy(A, 0, B, 0, n)`

위치: [`HW3.java` 28행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L28)

```java
arraycopy(A, 0, B, 0, n);   // 배열 복사
```

이 함수는 위의 import 때문에 이렇게 짧게 쓸 수 있습니다:

위치: [`HW3.java` 5행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L5)

```java
import static java.lang.System.arraycopy;
```

원래는 아래처럼 써야 합니다.

```java
System.arraycopy(A, 0, B, 0, n);
```

---

### 역할
배열 `A`의 내용을 `B`에 **빠르게 복사**합니다.

### 매개변수 의미
```java
arraycopy(원본배열, 원본 시작 인덱스, 대상배열, 대상 시작 인덱스, 복사 개수)
```

즉,

```java
arraycopy(A, 0, B, 0, n)
```

은

- `A`의 `0`번부터
- `n`개를
- `B`의 `0`번부터 복사

한다는 뜻입니다.

---

### 왜 썼는가?
좌표 압축을 하려면 **정렬된 배열**이 필요합니다.  
그런데 원래 입력 순서는 마지막 출력에서 꼭 필요합니다.

즉:

- `A`: 원래 순서를 유지해야 함
- `B`: 정렬해서 압축 순위를 계산하는 용도

그래서 `A`를 그대로 두고, 복사본 `B`를 정렬하는 것입니다.

---

### 왜 그냥 `B = A;`를 쓰지 않았는가?

이 부분이 매우 중요합니다.

```java
B = A;
```

라고 하면 **복사**가 아니라 **같은 배열을 가리키는 참조 공유**가 됩니다.

즉:
- `A`와 `B`가 같은 메모리를 바라봄
- `Arrays.sort(B)`를 하면 `A`도 함께 정렬되어 버림

그러면 원래 입력 순서를 잃어버려서 마지막 출력이 틀어집니다.

따라서 **실제 값 복사**가 필요하고, 그 역할을 `arraycopy`가 합니다.

---

### 왜 `for`문 복사 대신 `arraycopy`를 썼는가?

예를 들면 이런 방식도 가능합니다.

```java
for (int i = 0; i < n; i++) {
    B[i] = A[i];
}
```

그런데 `arraycopy`를 쓴 이유는:

1. **의도가 명확함**  
   → “배열 복사”를 한 줄로 명시
2. **성능이 좋음**  
   → JVM 내부 최적화 가능
3. **코드가 짧고 실수 가능성이 적음**

즉, 이 문제처럼 배열 전체를 복사할 때 아주 적절합니다.

## 3-6. `Arrays.sort(B)`

위치: [`HW3.java` 29행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L29)

```java
Arrays.sort(B);  // B를 오름차순으로 정렬
```

### 역할
배열 `B`를 **오름차순 정렬**합니다.

### 왜 썼는가?
좌표 압축의 핵심은  
“어떤 값보다 작은 **서로 다른 값의 개수**”를 구하는 것입니다.

이걸 쉽게 계산하려면 값들을 정렬해서 순서대로 보면 됩니다.

예를 들어 `B`가 정렬되면:

```text
-10, -9, 2, 4, 4
```

이제 왼쪽에서 오른쪽으로 가면서  
처음 등장하는 값마다 순위를 0, 1, 2, 3... 붙이면 됩니다.

---

### 왜 정렬이 필요한가?
정렬하지 않으면:

- 어떤 값이 더 작은지
- 서로 다른 값이 몇 개인지
- 각 값의 순위를 어떻게 줄지

를 한 번에 파악하기 어렵습니다.

정렬하면 같은 값들이 붙고, 작은 값부터 순서가 잡히기 때문에  
**중복 제거 + 순위 부여**가 쉬워집니다.

---

### 이 문제에서의 시간 복잡도 의미
`Arrays.sort(int[])`는 primitive 배열 정렬이고, 일반적으로 매우 빠르게 동작합니다.  
정렬 비용은 대략 `O(n log n)`입니다.

`N = 1,000,000`일 때도 좌표 압축의 대표 정석 풀이가 보통 정렬 기반이므로 적절한 선택입니다.

---

### 왜 `A`가 아니라 `B`를 정렬하는가?
원래 배열 `A`는 출력 시 **원래 입력 순서**가 필요합니다.  
만약 `A`를 정렬해버리면 결과를 원래 순서로 출력할 수 없습니다.

그래서:

- `A`는 원본 유지
- `B`는 정렬용 보조 배열

입니다.

---

## 3-7. `new HashMap<>()`

위치: [`HW3.java` 30행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L30)

```java
HashMap<Integer, Integer> rank = new HashMap<>();
```

### 역할
정수 값을 키로, 그 값의 압축 결과(순위)를 값으로 저장하는 해시맵을 만듭니다.

즉 이런 매핑을 저장합니다:

```text
원래 값 -> 압축된 값
```

예:
```text
-10 -> 0
-9  -> 1
2   -> 2
4   -> 3
```

---

### 왜 썼는가?
정렬 후에 각 값의 압축 순위를 계산한 뒤,  
원래 배열 `A[i]`가 나왔을 때 **즉시 그 압축값을 찾기 위해서**입니다.

즉:
- `rank.get(A[i])` 한 번으로 결과를 찾을 수 있음

---

### 왜 배열이 아니라 `HashMap`인가?
이 문제의 좌표 값 범위는:

```text
-10^9 <= Xp <= 10^9
```

범위가 너무 큽니다.  
배열 인덱스로 직접 쓰기 어렵습니다.

예를 들어 배열로 하려면:
- 음수 처리 필요
- 20억 크기 수준의 인덱싱 범위 문제
- 메모리 낭비가 심함

반면 `HashMap`은 **실제로 등장한 값만 저장**하면 되므로 효율적입니다.

---

### 왜 key와 value가 둘 다 `Integer`인가?
자바의 제네릭 컬렉션은 primitive 타입 `int`를 직접 못 써서,  
wrapper 클래스인 `Integer`를 사용합니다.

즉:
- key: 원래 좌표값
- value: 압축 순위

## 3-8. `rank.containsKey(B[i])`

위치: [`HW3.java` 33행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L33)

```java
if (!rank.containsKey(B[i])) {
```

### 역할
해시맵에 `B[i]`라는 키가 **이미 등록되어 있는지 확인**합니다.

### 왜 썼는가?
정렬된 배열에는 중복값이 있을 수 있습니다.

예:
```text
-10, -9, 2, 4, 4
```

여기서 `4`는 두 번 나옵니다.  
좌표 압축에서는 **서로 다른 값** 기준으로만 순위를 증가시켜야 합니다.

그래서:

- 처음 보는 값이면 순위 부여
- 이미 본 값이면 건너뜀

이 필요하고, 그 확인용이 `containsKey()`입니다.

---

### 왜 중요한가?
이 조건이 없으면 중복값마다 순위가 증가해 버립니다.

예를 들어 잘못 처리하면:
```text
-10 -> 0
-9  -> 1
2   -> 2
4   -> 3
4   -> 4   // 잘못됨
```

이런 문제가 생깁니다.

하지만 좌표 압축은 **같은 값은 같은 압축값**을 가져야 하므로  
중복 체크가 필수입니다.

## 3-9. `rank.put(B[i], rankCount++)`

위치: [`HW3.java` 34행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L34)

```java
rank.put(B[i], rankCount++);
```

### 역할
해시맵에
- 키: `B[i]`
- 값: 현재 순위 `rankCount`

를 저장합니다.

그리고 저장 후 `rankCount`를 1 증가시킵니다.

---

### 왜 썼는가?
정렬된 서로 다른 값에 대해 압축 순위를 붙여야 하기 때문입니다.

예를 들어 정렬된 서로 다른 값이:
```text
-10, -9, 2, 4
```

이면

- `-10 -> 0`
- `-9 -> 1`
- `2 -> 2`
- `4 -> 3`

처럼 순서대로 저장합니다.

---

### `rankCount++`의 의미
후위 증가 연산자입니다.

```java
rank.put(B[i], rankCount++);
```

은 개념적으로:

```java
rank.put(B[i], rankCount);
rankCount = rankCount + 1;
```

와 같습니다.

즉,
- 현재 값을 저장하고
- 그 다음에 증가합니다.

---

### 왜 별도 변수 `rankCount`를 뒀는가?
정렬된 서로 다른 값의 개수를 세면서 그 값 자체를 압축 결과로 쓰기 위함입니다.

이 변수는 곧  
“지금까지 등장한 서로 다른 작은 값의 수”를 의미합니다.

즉 문제의 요구사항과 정확히 맞아떨어집니다.

## 3-11. `rank.get(A[i])`

위치: [`HW3.java` 39행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L39)

```java
sb.append(rank.get(A[i]));
```

### 역할
원래 값 `A[i]`에 대응하는 압축 결과(순위)를 해시맵에서 꺼냅니다.

예를 들어
```text
A[i] = 4
```
이면
```text
rank.get(4) = 3
```
을 반환합니다.

---

### 왜 썼는가?
출력은 반드시 **원래 입력 순서대로** 해야 합니다.

정렬된 `B`로 압축 순위 표를 만들었지만,  
실제 출력은 `A`를 다시 순회하면서 해야 합니다.

따라서 각 `A[i]`에 대해 “압축된 값이 뭐였지?”를 즉시 찾기 위해 `get()`을 씁니다.

---

### 왜 빠른가?
`HashMap`은 평균적으로 키 조회가 빠릅니다.  
그래서 `n`개의 원소에 대해 하나씩 결과를 찾는 데 적합합니다.

## 3-12. `sb.append(...)`

위치:
- [`HW3.java` 39행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L39)
- [`HW3.java` 40행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L40)

```java
sb.append(rank.get(A[i]));
if (i < n - 1) sb.append(" ");
```

### 역할
`StringBuilder` 뒤에 문자열 또는 값을 이어 붙입니다.

### 이 코드에서 하는 일
1. 압축된 숫자를 붙임
2. 마지막 원소가 아니면 공백 `" "`도 붙임

---

### 왜 공백 조건을 넣었는가?
출력 형식 때문에 숫자들 사이에는 공백이 필요합니다.  
하지만 마지막 숫자 뒤에 굳이 공백을 붙이지 않도록 한 것입니다.

즉:
- 원하는 출력: `2 3 0 3 1`
- 피하고 싶은 출력: `2 3 0 3 1 `

온라인 저지에서는 마지막 공백을 허용하는 경우도 많지만,  
이 코드는 깔끔하게 맞춰 출력하려고 조건을 넣었습니다.

---

### `append`가 좋은 이유
`append`는 여러 타입을 문자열로 바꿔서 효율적으로 덧붙일 수 있습니다.

여기서는 `Integer`/`int`, `" "`를 계속 이어 붙이는 데 적합합니다.

# 4. “왜 이런 함수 조합이 필요한가?”를 문제 관점에서 정리

이 문제의 핵심은:

- 값의 크기 범위는 매우 큼 (`-10^9 ~ 10^9`)
- 원소 개수도 매우 큼 (`최대 1,000,000`)
- 중복값 존재 가능
- 원래 입력 순서로 결과 출력해야 함

그래서 각 함수가 딱 이런 역할 분담을 합니다.

---

## 입력 처리
- `Scanner`
- `nextInt`

→ 숫자를 읽기 위해 사용

---

## 원본 보존
- `arraycopy`

→ `A`는 그대로 두고, 정렬용 복사본 `B`를 만들기 위해 사용

---

## 순위 계산 준비
- `Arrays.sort`

→ 작은 값부터 순서대로 보기 위해 사용

---

## 중복 제거 + 순위 저장
- `HashMap`
- `containsKey`
- `put`

→ 각 서로 다른 값에 대해 압축 순위를 저장하기 위해 사용

---

## 원래 순서대로 결과 출력
- `get`
- `StringBuilder`
- `append`
- `println`

→ `A`를 다시 보면서 압축 결과를 빠르고 깔끔하게 출력하기 위해 사용

# 5. 특히 중요한 함수 4개만 다시 아주 직관적으로 설명

---

## `arraycopy`를 왜 썼나?
**원본 배열 `A`를 보존하면서 정렬용 배열 `B`를 만들기 위해서**입니다.  
정렬은 해야 하지만, 출력은 원래 순서대로 해야 하므로 복사본이 필요합니다.

---

## `Arrays.sort`를 왜 썼나?
**값들의 크기 순서를 알아야 압축 순위를 매길 수 있기 때문**입니다.  
정렬하면 작은 값부터 차례대로 보면서 순위를 붙일 수 있습니다.

---

## `HashMap`을 왜 썼나?
**값 범위가 너무 커서 배열로 직접 매핑할 수 없기 때문**입니다.  
실제로 등장한 값만 저장해서 메모리와 조회를 효율적으로 처리합니다.

---

## `StringBuilder`를 왜 썼나?
**출력 데이터가 매우 많을 수 있어서 문자열을 효율적으로 만들기 위해서**입니다.  
`+` 연산 반복보다 훨씬 적합합니다.

---

# 6. 이 코드에서 함수가 없으면 어떤 문제가 생기나?

### `arraycopy`가 없으면
`B`를 못 만들거나, `A`를 직접 정렬해서 원래 순서를 잃음

### `Arrays.sort`가 없으면
값의 상대적 크기 순서를 쉽게 알 수 없음

### `containsKey`가 없으면
중복값에 대해 순위가 여러 번 증가해서 틀린 결과 나옴

### `HashMap.get`이 없으면
원래 배열의 각 값에 대한 압축 결과를 빠르게 찾기 어려움

### `StringBuilder`가 없으면
큰 입력에서 출력 문자열 구성 성능이 나빠질 수 있음

# 7. 예시로 코드가 실제로 어떻게 동작하는지

입력:
```text
5
2 4 -10 4 -9
```

## 1단계: 입력
`A = [2, 4, -10, 4, -9]`

## 2단계: 복사
`B = [2, 4, -10, 4, -9]`

## 3단계: 정렬
`B = [-10, -9, 2, 4, 4]`

## 4단계: 맵 생성
반복하면서:

- `-10` 처음 등장 → `rank.put(-10, 0)` → `rankCount = 1`
- `-9` 처음 등장 → `rank.put(-9, 1)` → `rankCount = 2`
- `2` 처음 등장 → `rank.put(2, 2)` → `rankCount = 3`
- `4` 처음 등장 → `rank.put(4, 3)` → `rankCount = 4`
- `4` 이미 존재 → 건너뜀

최종 맵:
```text
-10 -> 0
-9  -> 1
2   -> 2
4   -> 3
```

## 5단계: 원래 순서대로 출력
`A`를 다시 보며:

- `2` → `2`
- `4` → `3`
- `-10` → `0`
- `4` → `3`
- `-9` → `1`

출력:
```text
2 3 0 3 1
```

# 8. 코드에서 더 깊게 보면 좋은 포인트

## `import static java.lang.System.arraycopy;`를 왜 했나?
위치: [`HW3.java` 5행](file:///D:/Github_Repo/DataStructure-Algorithm/JAVA/chap1/src/HW3.java#L5)

이건 **정적 import**입니다.

원래는 이렇게 써야 합니다:

```java
System.arraycopy(A, 0, B, 0, n);
```

그런데 정적 import를 하면 클래스 이름 `System`을 생략하고

```java
arraycopy(...)
```

만 써도 됩니다.

### 왜 이렇게 했을까?
- 코드가 조금 더 짧아짐
- 자주 쓰는 정적 메서드를 간단히 호출 가능

다만, 초보자 입장에서는 오히려 “이 함수가 어디서 왔지?” 헷갈릴 수 있어서  
가독성 취향 차이가 있습니다.

# 9. 성능 관점에서 이 함수 선택이 적절한가?

## 적절한 부분
- `arraycopy` → 빠른 복사
- `Arrays.sort` → 정렬 기반 좌표 압축의 정석
- `HashMap` → 큰 값 범위 처리 적절
- `StringBuilder` → 대량 출력 적절

## 약간 아쉬울 수 있는 부분
- `Scanner`는 입력이 매우 많을 때 느릴 수 있음

즉 알고리즘 아이디어는 좋고,  
입력 방식만 더 빠르게 바꾸면 성능 안정성이 더 좋아질 수 있습니다.
