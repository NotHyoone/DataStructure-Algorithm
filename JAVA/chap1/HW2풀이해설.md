## 문제 핵심

이 문제는 **단일 연결 리스트를 삽입 정렬(Insertion Sort)로 정렬**하는 것입니다.  
배열과 달리 연결 리스트는 인덱스로 바로 접근이 안 되기 때문에, 정렬할 때 **노드 포인터 재연결**이 핵심입니다.

---

## 파일 구조와 역할 (`src/HW2.java`)

### 1) `class ListNode`
연결 리스트의 기본 단위(노드)를 정의합니다.

- `int val`
    - 노드의 실제 값 저장.
- `ListNode next`
    - 다음 노드를 가리키는 참조(포인터).
- 생성자 3개
    - `ListNode()`
        - 기본 생성. 필요 시 빈 노드 생성 가능.
    - `ListNode(int val)`
        - 값만 지정해 노드 생성할 때 편함.
    - `ListNode(int val, ListNode next)`
        - 값과 다음 노드를 동시에 지정할 때 사용.

**왜 필요?**  
문제 자체가 “연결 리스트 정렬”이므로, 노드 구조(`val`, `next`)가 있어야 정렬 로직을 구현할 수 있습니다.

### 3) `class Solution2`
실제 정렬 알고리즘 구현.

#### `public ListNode insertionSortList(ListNode head)`

이 함수가 문제의 핵심입니다.

## `insertionSortList` 상세 해설 (핵심)

### (1) 예외/기저 처리
```java
if (head == null || head.next == null) return head;
```
- 노드가 0개/1개면 이미 정렬 상태.
- 불필요한 반복을 줄이고, null 접근 오류를 방지.

**왜 필요?**  
정렬 알고리즘의 기본 안전장치 + 성능 최적화.

---

### (2) 더미 노드 준비
```java
ListNode dummy = new ListNode(0);
ListNode curr = head;
```
- `dummy`: 정렬된 리스트의 가짜 머리.
- `curr`: 원본 리스트에서 하나씩 꺼내는 포인터.

**왜 `dummy`가 중요한가?**
- 삽입 위치가 “맨 앞”일 때 처리가 훨씬 간단해집니다.
- head 교체 케이스를 별도 분기 없이 통일적으로 처리 가능.
- 연결 리스트 삽입 로직의 버그를 크게 줄여줍니다.

---

### (3) 원본 리스트 순회하며 하나씩 삽입
```java
while(curr != null) {
    ListNode next = curr.next;
    ...
    curr = next;
}
```
- `next = curr.next`를 **먼저 저장**하는 것이 매우 중요.
- 왜냐하면 곧 `curr.next`를 삽입 과정에서 덮어쓰기 때문.

**왜 필요?**  
현재 노드를 정렬 리스트에 끼워 넣는 순간 원본 연결이 끊기므로,  
다음 순회 위치를 미리 백업하지 않으면 나머지 노드를 잃어버립니다.

---

### (4) 삽입 위치 탐색
```java
ListNode prev = dummy;
while(prev.next != null && prev.next.val <= curr.val) {
    prev = prev.next;
}
```
- 정렬된 리스트(`dummy.next`부터 시작)에서 `curr.val`이 들어갈 자리 직전 노드 `prev`를 찾음.
- 조건 `<=`를 써서 **같은 값이면 뒤쪽에 삽입**됨.

**왜 `<=`인가?**
- 같은 값의 상대적 순서를 보존하는 **안정 정렬(stable sort)** 성질을 갖게 됩니다.
- 예: 기존에 먼저 있던 3이, 나중에 온 3보다 앞에 유지됨.

---

### (5) 실제 삽입
```java
curr.next = prev.next;
prev.next = curr;
```
- 연결 리스트 삽입의 정석 2줄.
1. `curr`이 원래 `prev` 다음 노드를 가리키게 만들고
2. `prev`가 `curr`을 가리키게 변경

**왜 이 순서인가?**  
순서를 바꾸면 기존 노드 참조를 잃어버릴 수 있습니다.

---

### (6) 정답 반환
```java
return dummy.next;
```
- 더미 다음이 진짜 정렬된 리스트의 시작 노드.

---

## 예시로 추적 (`-1 -> 5 -> 3 -> 4 -> 0`)

정렬 리스트 초기: `dummy -> null`

1. `curr=-1` 삽입  
   정렬: `-1`
2. `curr=5` 삽입  
   정렬: `-1 -> 5`
3. `curr=3` 삽입 위치: `-1` 뒤  
   정렬: `-1 -> 3 -> 5`
4. `curr=4` 삽입 위치: `3` 뒤  
   정렬: `-1 -> 3 -> 4 -> 5`
5. `curr=0` 삽입 위치: `-1` 뒤  
   정렬: `-1 -> 0 -> 3 -> 4 -> 5`

최종 출력과 일치합니다.

---

## 복잡도

- 시간복잡도: **O(n²)**
    - 각 노드마다 삽입 위치를 앞에서부터 찾기 때문.
- 공간복잡도: **O(1)** (추가 노드 배열 없이 포인터만 사용)
    - `dummy`와 포인터 변수만 추가 사용.

---

## 정리

이 풀이의 핵심은 다음 3가지입니다.

- `dummy`로 head 변경 케이스를 단순화
- `next` 백업으로 원본 리스트 손실 방지
- `prev` 탐색 후 2줄 삽입으로 안전한 포인터 재연결
